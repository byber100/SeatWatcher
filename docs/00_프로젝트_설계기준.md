# SeatWatcher 프로젝트 설계기준

## 0. 문서 역할

- `README.md`: 외부 사용자와 방문자에게 SeatWatcher가 무엇인지, 무엇을 지원하는지, 어떻게 실행하는지를 소개하는 공개 안내 문서다.
- `docs/`: 사용자와 ChatGPT가 개발 과정에서 요구사항, 판정 기준, 구현 방향, 검증 결과를 맞추기 위한 협업 문서 공간이다.
- 외부 소개 목적의 설명은 README에 두고, 개발 판단과 세부 규칙은 docs에 기록한다.

## 1. 목적

SeatWatcher는 철도와 버스의 취소표/예약 가능 좌석을 읽기 전용으로 반복 조회하고, 새로 이용 가능한 후보 또는 기존 후보보다 이용 품질이 좋아진 경우 알림하는 도구다.

## 2. 보안 및 저장소 원칙

- 실제 KORAIL/Kakao 인증값은 Git 이력에 저장하지 않는다.
- 저장소의 `.env`와 `env.example.txt`는 **빈 템플릿**으로만 추적한다. 실제 비밀값은 넣지 않는다.
- 실제 로컬 인증값은 `.env.local`에 저장하며 `.gitignore`로 추적을 차단한다.
- 환경변수 우선순위는 `OS 환경변수 > .env.local > .env 템플릿`이다.
- `env_loader.py`는 빈 템플릿 값은 환경변수로 등록하지 않는다.
- 기존 로컬 `.env`에 값이 남아 있는 환경과의 호환을 위해 `.env`도 마지막 fallback으로 읽지만, 신규/정상 운영에서는 `.env.local`만 사용한다.
- `.runtime/`, `.venv/`, 캐시와 런타임 토큰/상태 파일은 추적하지 않는다.
- `watch_targets.json`은 공개 기본 설정이며 실제 개인 이동 일정을 넣지 않는다.
- 실제 개인 감시 일정은 `watch_targets.local.json`에 저장하고 Git 추적에서 제외한다.
- Google Drive가 생성하는 `*.gdoc` 로컬 포인터는 문서 원문이 아니므로 Git 추적에서 제외한다. 개발 협업 원문은 `docs/*.md`로 추적한다.

## 3. 감시 공급자

- 철도: KORAIL 읽기 전용 조회
- 버스: KOBUS, 티머니 시외버스, 버스타고
- 공급자 장애는 전체 감시 사이클을 중단시키지 않고 경고로 분리한다.

## 4. 철도 규칙

- 모든 철도 target에서 직통과 자동 환승을 각각 조회한다.
- 터미널에는 직통/환승 검색 과정과 실제 시간표를 상세히 출력한다. 이 디버그 출력은 축소하지 않는다.
- 환승 시간표는 직통 좌석 수와 무관하게 항상 조회·표시한다.
- `transfer_display_direct_threshold`는 환승 검색/표시가 아니라 알림 후보 승격에만 사용한다.
- 사용 가능한 환승 후보는 두 구간 모두 실제 이용 가능한 좌석 상태여야 한다. 예약대기는 직통에만 적용한다.
- 환승 열화 판정은 같은 출발시각 후보끼리 총 소요시간을 먼저 비교하고, 동률이면 지정좌석 예약 > 자유석 > 입석/혼합 순으로 본다. 열차 종류 자체는 우열 기준이 아니다.
- 과도한 우회 환승은 지리 필터로 제외한다.

## 5. 상태 및 알림 규칙

- `ALERT-001`: 같은 편의 상태가 직전 성공 알림 이후 그대로면 polling 때마다 반복 알림하지 않는다.
- `ALERT-002`: 같은 편이 현재 **실제로 예매 가능한 상태**인 동안 잔여석 수 또는 이용 가능 형태가 바뀌면 다시 알린다. 잔여 3석→2석, 2석→4석처럼 증가·감소 방향과 무관하게 현재 예매 가능 상태가 변하면 알림 대상이다.
- `ALERT-003`: `매진` 또는 예약 불가 상태로 바뀐 사실 자체는 알리지 않는다. 다만 내부 상태는 갱신해 두었다가 이후 같은 편이 다시 예약 가능해지면 다시 알린다.
- `ALERT-004`: 예매 가능한 상태에는 지정좌석, 일반실/특실 예약 가능, 자유석, 입석, 입석+좌석 혼합 등 KORAIL/버스 공급자가 실제 구매 가능한 것으로 반환한 모든 형태를 포함한다.
- `ALERT-005`: 예약대기는 실제 좌석과 분리된 기존 별도 알림 상태로 유지한다. 예약대기→실제 예매 가능 전환은 `예약 가능`으로 다시 알린다.
- `ALERT-006`: 기존 예매 가능 상태에서 더 좋은 좌석 형태로 바뀌면 `좌석 품질 상승`, 그 외 잔여석 수 감소/증가 또는 예매 가능 형태 변경은 `좌석 변동`으로 표시한다.
- `ALERT-007`: 같은 polling cycle에서 여러 편의 변동이 생겨도 Kakao 메시지는 편별로 난사하지 않고 **cycle당 1개의 묶음 알림**으로 전송한다. 메시지에는 총 변동 건수와 최대 2개의 핵심 항목만 읽기 좋게 표시하고 전체 상세는 `예매 확인` 링크에서 본다.
- `ALERT-008`: `예매 확인` 링크는 GitHub Pages의 정적 상세 화면으로 연결한다. 상세 데이터는 저장소나 서버 파일에 쓰지 않고 URL `#fragment`에 넣어 브라우저에서만 해석한다. KORAIL 예매 버튼은 알림편 출발시각 60분 전을 10분 단위로 내린 시각을 조회 시작으로 삼아 **동일 날짜·출발역·도착역의 주변 시간대**를 연다. 모바일 코레일+에는 검증된 `korailtalk://navigation?view=booking`와 `srtDep/srtArv/srtDt/srtTm` extras를 전달하고, 실패 또는 데스크톱에서는 같은 조건의 공식 KORAIL 웹 조회로 fallback한다.
- `ALERT-008-BUS`: 버스 카드의 예매 동선은 원 조회 공급자와 관계없이 **티머니GO**로 통일한다. Android에서는 package `kr.co.tmoney.tia`를 직접 연다. 공개적으로 검증된 `출발터미널/도착터미널/날짜/시간` 티머니GO 딥링크 계약이 확인될 때까지 검색조건을 자동 복사해 앱을 열고, 확인되지 않은 URI parameter를 추측해 넣지 않는다.
- `ALERT-009`: 일반 테스트 알림은 합성 데이터를 기본으로 한다. 다만 **앱 딥링크의 날짜·출발지·도착지·시간 prefill을 검증하는 통합 테스트**는 실존 역/터미널과 실제 예매 가능 날짜를 사용할 수 있으며, 이 경우 제목과 상태에 `조회조건 테스트 · 실제 운행편 아님`, `실제 좌석 알림 아님`을 명시해 실제 운행·좌석 알림과 혼동하지 않게 한다.
- 알림 여부와 관계없이 터미널 디버그 출력은 상세 상태를 유지한다.
- Kakao 알림은 사용자가 실제로 보는 출력이므로 터미널 출력과 별개로 다룬다.

## 6. 최종 이동 규칙

장거리 교통 자체가 예약 가능하더라도 최종 목적지까지 실제 이동 가능해야 알림 후보가 된다. 공개 저장소에는 사용자의 정확한 생활권 목적지 대신 일반화된 목적지 표현만 유지한다.

## 7. polling

- `PERF-001`: 기본 polling 간격은 `poll_interval_seconds`로 관리하며 현재 공개 기본값은 120초다.
- `PERF-002`: polling 간격은 **이전 cycle 종료 후 추가 대기시간**이 아니라 cycle 시작 시각 간 목표 간격으로 해석한다. 조회 자체에 시간이 걸렸으면 그만큼 다음 sleep을 줄여 불필요한 공백을 없앤다.
- `PERF-003`: cycle 내부에서 완전히 동일한 공급자 조회 조건은 한 번만 실행하고 결과를 target별로 재사용한다. 현재 로컬 설정에 중복 target이 없더라도 이후 설정 중복으로 같은 API를 반복 호출하지 않게 한다.
- `PERF-004`: 조회 빈도를 높이더라도 서비스 차단/NetFunnel/비정상 응답 징후가 없는 범위에서 보수적으로 조정한다. 필수 직통/환승 조회를 임의로 생략해 호출 수를 줄이지 않는다.
- `PERF-005`: 버스와 철도는 서로 다른 공급자이므로 같은 cycle에서 병렬로 조회해 네트워크 대기시간을 겹친다. 반면 동일 KORAIL 계정의 직통/환승/target 요청은 차단 위험 검증 전까지 병렬화하지 않고 순차 조회한다.
- `PERF-006`: KORAIL pagination은 현재 페이지에 target 종료시각을 초과한 출발편이 이미 포함되면 이후 페이지를 조회하지 않는다. 같은 종료시각의 다른 편 누락을 피하기 위해 정확히 종료시각과 같은 경우에는 다음 페이지 가능성을 보존한다.
- `PERF-007`: 현재 작동 점검용 `--wide-rail-test`는 저장된 개인 감시 설정을 변경하지 않고 실행 시에만 **2026-09-18 서울↔동대구 양방향 2개 target을 `05:00~23:59`**로 추가한다. 테스트 로그는 직통 운행 수와 **매진편 수를 별도로 집계**한다. 임시 target의 첫 성공 cycle은 현재 이용 가능 상태를 baseline으로만 저장해 신규 알림 폭주를 막고, 그 다음 cycle부터 좌석 변동과 매진/미노출 후 재등장을 정상 알림한다. 매진편 자체는 알림하지 않는다. 테스트 종료 후 플래그 없이 재시작하면 원래 범위로 복귀한다.

## 8. 설정 로딩 계약

- `CONFIG-001`: `watch_targets.local.json`이 존재하면 `watcher.py`는 이를 실제 운영 설정으로 우선 사용한다.
- `CONFIG-002`: 로컬 설정 파일이 없을 때만 Git에 추적되는 `watch_targets.json`을 사용한다.
- `CONFIG-003`: 두 파일의 JSON 형식은 동일하게 유지해 공개 예시와 로컬 운영 설정이 같은 코드 경로를 사용하게 한다.
- `CONFIG-004`: 공개 `watch_targets.json`에는 개인 일정이나 정확한 개인 목적지를 기록하지 않는다.

## 8-1. 클라우드 운영 계약

- `CLOUD-001`: 최종 자동 감지는 사용자의 PC가 꺼져 있어도 계속되어야 한다. 로컬 PC를 상시 실행기나 웹서버로 사용하지 않는다.
- `CLOUD-002`: 기본 운영 대상은 **Oracle Cloud Infrastructure Always Free Compute**의 소형 Ubuntu VM이다. 현재 권장 기준은 `VM.Standard.A1.Flex` 1 OCPU / 1 GB 메모리 또는 계정에서 제공되는 Always Free x86 micro이며, VM은 공개 웹 애플리케이션을 제공하지 않고 `watcher.py --watch --notify` 프로세스만 실행한다. Python 3.11 이상이 필요하므로 Ubuntu 24.04 이상을 사용한다.
- `CLOUD-003`: VM의 `systemd`가 SeatWatcher를 자동 시작·재시작한다. 감시 상태 파일과 Kakao 토큰은 VM의 비공개 로컬 디스크에 유지해 polling 사이 상태가 보존되도록 한다.
- `CLOUD-004`: `.env.local`, `watch_targets.local.json`, `.runtime/kakao_tokens.json`은 GitHub에 올리지 않고 사용자가 VM으로 직접 복사한다. `deploy/cloud_vm_manage.py`는 이 세 파일이 없는 상태에서 운영 서비스를 시작하지 않는다.
- `CLOUD-005`: 웹 상세 화면은 GitHub Pages가 담당하며 SeatWatcher VM에는 HTTP 서버나 공개 인바운드 포트를 열지 않는다. 개발 협업용 `docs/`를 Pages 루트로 공개하지 않고, 정적 웹 파일만 둔 `gh-pages` 브랜치 `/(root)`를 Pages 소스로 사용한다.
- `CLOUD-006`: GitHub Actions는 Pages 배포나 개발 검증에는 사용할 수 있지만 SeatWatcher 상시 polling 실행기로 사용하지 않는다. 감시 프로세스는 장기 실행 목적의 클라우드 VM에서 동작한다.
- `CLOUD-007`: Oracle Always Free VM은 공식 정책상 장기간 낮은 CPU·네트워크·메모리 사용률이면 유휴 인스턴스로 회수될 수 있다. 따라서 이를 절대적 SLA로 간주하지 않고 운영 상태를 확인하며, 회수 시 같은 배포 스크립트로 재프로비저닝할 수 있게 비공개 설정 백업을 로컬에 유지한다.

## 9. Git 운영 계약

- `GIT-001`: 로컬 저장소의 `origin`은 `https://github.com/byber100/SeatWatcher.git`이며 작업 기준 브랜치는 `main`이다.
- `GIT-002`: `main`은 `origin/main`을 추적한다.
- `GIT-003`: 평소 개발은 **로컬 우선**으로 진행한다. 기능 단위 수정이 끝나고 해당 변경에 필요한 구문 검사·테스트·빌드·런타임 검증이 통과하면, 사용자에게 별도 커밋 지시를 다시 묻지 않고 로컬 `main`에 자동 커밋한다.
- `GIT-004`: 자동 커밋 직전에는 워크스페이스의 기존 `git-project`/`git-commit` 규칙을 그대로 적용한다. 커밋 메시지 형식, 검증 상태 표식, 스테이징 범위 분리는 기존 스킬을 SSOT로 삼는다.
- `GIT-005`: 검증 또는 빌드가 실패한 변경은 정상 완료 커밋으로 만들지 않는다. 수정 후 관련 검증을 다시 통과한 시점에 커밋한다.
- `GIT-006`: **커밋과 push를 분리한다.** 로컬 커밋은 작업 중 계속 누적할 수 있지만 `git push origin main`은 사용자가 `깃에 올려`, `push`, `GitHub에 반영` 등 원격 반영을 명시했을 때만 수행한다.
- `GIT-007`: 사용자가 원격 반영을 지시하면 그 시점까지 로컬 `main`에 누적된 정상 커밋을 확인하고 한 번에 `origin/main`으로 push한다. push 전 필요하면 `git pull --ff-only`로 원격 선행 변경을 안전하게 동기화한다.
- `GIT-008`: GitHub Contents/API로 제품 파일을 직접 수정하지 않고 로컬 Git commit/push를 통해 반영한다.
- `GIT-009`: 동기화 전 로컬 파일이 원격과 다를 때는 삭제나 덮어쓰기보다 별도 로컬 보존점 또는 명시적 비교를 먼저 만든다.
- `GIT-010`: `README.md`와 `docs/*.md`는 Git 추적 대상이며 README는 외부 소개/사용법, docs는 개발 협업 SSOT 역할을 유지한다.
- `GIT-011`: 다른 채팅에서 SeatWatcher 작업을 재개할 때도 이 Git 운영 계약을 먼저 적용하며, 단순히 새 채팅이라는 이유로 누적 로컬 커밋을 자동 push하지 않는다.
- `GIT-012`: 원격 작업 시작 전 Local `project_info`에서 전용 `git_fetch`, `git_pull_ff_only`, `git_push` 노출 여부를 먼저 확인한다. `.local-mcp/server.py` 원본을 수정했더라도 활성 MCP를 재시작하기 전에는 기능이 사용 가능하다고 간주하지 않는다.
- `GIT-013`: Local의 generic `run_git`에 네트워크 원격 명령을 억지로 허용하지 않는다. 원격 반영은 전용 Git 도구를 사용하고, Google Drive는 문서·소스 확인 폴백으로 자동 활용하되 Git commit history push의 대체 수단이라고 주장하지 않는다.

## 10. 검증 기준

변경 후 최소한 다음을 확인한다.

- Python 구문 검사 통과
- 공개/로컬 JSON 설정 파싱 통과
- `watch_targets.local.json`이 존재하면 실제 로더가 해당 파일을 선택하는지 확인
- 저장소 공개본에 실제 인증값/개인 일정/정확한 개인 목적지가 없는지 검사
- `.env`는 빈 템플릿이고 `.env.local`은 Git 추적 대상이 아닌지 확인
- `watch_targets.local.json`, `.runtime/`, `*.gdoc`가 Git 추적 대상이 아닌지 확인
- GitHub push는 사용자 원격 반영 지시가 있을 때만 수행하며, 그때 `main`과 `origin/main`의 push/pull 왕복을 검증한다.
- 실제 외부 조회를 수행한 경우 성공 여부와 차단/오류 징후를 별도로 기록
- 묶음 알림 smoke에서 동일 cycle의 여러 변동이 Kakao 발송 1회로 합쳐지고, 발송 실패 시 해당 변동 snapshot이 롤백되어 다음 cycle에 재시도되는지 확인
- GitHub Pages 상세 링크의 URL fragment payload가 서버 저장 없이 브라우저에서 복원 가능하며 공급자별 예매 버튼이 생성되는지 확인
- 클라우드 운영 스크립트가 비공개 설정 3종이 없는 상태에서 서비스를 시작하지 않고, systemd 서비스가 `--watch --notify`로 등록되는지 정적 검증
- `watcher.py`를 import하는 smoke는 반드시 프로젝트 `.venv` Python으로 직접 실행한다. 시스템 Python에서 import하면 `_ensure_project_python()`의 재실행 경로가 `watcher.py` 본 실행으로 이어져 실제 공급자 조회가 시작될 수 있으므로 금지한다.

## 11. 현재 Git 기준 상태

- 공개 저장소의 `watch_targets.json`은 빈 target 목록을 가진 안전한 기본값으로 유지한다.
- 실제 로컬 감시 조건은 Git 제외 `watch_targets.local.json`에 보존한다.
- 원격 공개본에서 발견된 Python 문법/문자열 오류는 로컬 검증 후 일반 Git commit/push로만 수정한다.
- 원격 동기화 전에 존재하던 로컬 작업 상태는 로컬 전용 보존 브랜치로 남겨 원본 비교가 가능하게 한다.
- 일반 개발 중 정상 검증을 마친 변경은 로컬 `main`에 자동 커밋하고, 원격 push는 사용자 지시까지 보류한다.

이 문서는 개발 협업용 SSOT다. 외부 사용자에게 보여줄 프로젝트 소개와 사용 안내는 `README.md`에서 관리한다. 채팅 간 인수인계는 `docs/01_작업일지.md`를 사용하며, 개인 일정 및 운영 비밀값은 Git 제외 로컬 설정에서 관리한다.

## 12. Pushover 보조 알림 정책

- `ALERT-010`: 기존 Kakao 묶음 알림은 유지하고, 동일한 `pending_events`를 입력으로 Pushover 보조 알림을 추가한다. 좌석변동 판정, 같은 상태 반복 방지, 매진 전환 무알림 판정은 수정하지 않는다.
- `ALERT-011`: Pushover에서 `notification.pushover.important_direct_departures`에 포함된 출발역의 **직통 열차**만 중요 그룹으로 분류한다. 중요 그룹은 설정된 업무시간 안에는 `vibrate`(진동만), 업무시간 밖에는 `off_work_sound` 유음으로 보낸다. Pushover `priority=1/2`는 업무시간 무음 요구와 충돌하므로 사용하지 않고 기본 `priority=0`을 사용한다.
- `ALERT-012`: 환승 열차와 버스는 항상 `silent_sound=none`으로 보낸다. 중요 출발역 목록에 포함되지 않은 다른 직통 열차도 예기치 않은 소리를 막기 위해 기본 무음 그룹으로 보낸다. 같은 cycle에 중요 그룹과 무음 그룹이 함께 있으면 Pushover는 그룹별로 최대 1회씩 묶어 보내며, Kakao는 기존대로 cycle당 1회만 보낸다.
- `ALERT-013`: Pushover의 `url`에는 기존 GitHub Pages 상세 URL을 그대로 넣고 `url_title`은 `예매 확인`으로 고정한다.
- `ALERT-014`: Kakao 전송을 먼저 수행한다. Kakao 실패 시 기존 snapshot 롤백/재시도 동작을 그대로 유지한다. Kakao 성공 후 Pushover 보조 전송이 실패하면 좌석 snapshot을 롤백하지 않아 이미 성공한 Kakao가 같은 상태에서 반복 발송되지 않게 하며, Pushover 실패는 경고 로그로 남긴다.
- `CONFIG-005`: 업무시간은 코드에 하드코딩하지 않고 `notification.work_hours` 설정의 `timezone`, `weekdays`, `start`, `end`로 관리한다. 공개/로컬 설정의 초기값은 `+09:00`, 월~금(`0..4`), `09:00~18:00`이며 사용 환경에 맞게 설정 파일에서 조정한다.
- `CONFIG-006`: Pushover 정책은 `notification.pushover`의 `enabled`, `important_direct_departures`, `work_sound`, `off_work_sound`, `silent_sound`로 관리한다. API 인증정보는 Git 제외 `.env.local`의 `SEATWATCHER_PUSHOVER_APP_TOKEN`, `SEATWATCHER_PUSHOVER_USER_KEY`에 저장하고 선택적으로 `SEATWATCHER_PUSHOVER_DEVICE`를 사용할 수 있다.
- `TEST-010`: 알림 정책 smoke에서 업무시간 중요 직통=`vibrate`, 업무 외 중요 직통=`off_work_sound`, 환승=`none`, 버스=`none`, 기타 직통=`none`을 확인한다.
- `TEST-011`: Pushover request smoke에서 `url`이 기존 상세 페이지 URL과 동일하고 `url_title=예매 확인`, `priority=0`인지 확인한다.
- `TEST-012`: 동일 상태 반복/매진 전환 무알림 smoke는 기존 검증을 그대로 통과해야 하며 Pushover 추가로 좌석 상태 판정 경로가 바뀌지 않아야 한다.
