# SeatWatcher 작업일지

이 문서는 **채팅 간 작업 인수인계용 요약**이다. 구현 판단의 최종 SSOT는 `./00_프로젝트_설계기준.md`이며, 실제 개인 감시 일정은 Git 제외 파일 `../watch_targets.local.json`에만 둔다.

## 작업 재개 규칙

- 새 채팅에서 SeatWatcher 작업을 이어갈 때 `./00_프로젝트_설계기준.md`와 이 파일을 먼저 읽는다.
- 이후 현재 코드와 `git status`/최근 커밋을 대조하고, 아래의 `다음 작업`부터 바로 진행한다.
- 기능 단위 작업이 끝나고 필요한 검증·빌드가 성공하면 기존 `git-project`/`git-commit` 규칙에 따라 **로컬 `main`에 자동 커밋**한다.
- GitHub push는 자동으로 하지 않는다. 사용자가 `깃에 올려`, `push`, `GitHub에 반영`처럼 원격 반영을 명시했을 때까지 로컬 커밋을 누적한다.
- 작업일지는 공개 Git 추적 문서이므로 실제 개인 일정·정확한 개인 목적지·인증정보는 기록하지 않는다.

### 현재 Git 운영 방식

1. 로컬에서 기능 단위로 수정한다.
2. 해당 기능의 구문 검사·테스트·빌드·필요한 런타임 검증을 수행한다.
3. 검증이 성공하면 기존 `git-project`/`git-commit` 규칙을 적용해 로컬 `main`에 자동 커밋한다.
4. 다음 기능 작업을 계속하며 로컬 커밋을 누적한다.
5. 사용자가 원격 반영을 지시하면 원격 변경을 안전하게 확인한 뒤 누적 커밋을 `origin/main`에 push한다.

## 기능 진행 현황

### 최근 완료

- KORAIL 직통과 자동 환승 조회 경로를 유지한다.
- pagination cursor 누락 시 출발시각 기반 fallback을 적용했다.
- 기차 출력은 실제 열차별 출발/도착시각, 열차명, 좌석상태를 표시한다.
- 환승 출력은 1구간/환승역/대기시간/2구간/각 구간 좌석상태를 표시한다.
- 환승 열화 판정은 열차 기종을 사용하지 않고 같은 출발시각 후보끼리 총 소요시간을 우선 비교하며, 동률이면 지정좌석 예약 > 자유석 > 입석·혼합 순으로 본다.
- 버스는 매진/0석을 포함해 실제 배차시간을 표시한다.
- 자정 넘김 철도 도착은 다음날 절대시각으로 계산해 last-mile을 판정한다.
- 특정 버스 공급자 노선도 last-mile 판정 경로에 포함했다.
- 철도 상태 품질을 지정좌석 > 자유석 > 입석·혼합 > 예약대기 순으로 관리하고, 같은 정확 여정의 품질 상승 시 재알림한다.
- 예약대기는 KORAIL 직통에서만 별도 후보로 감지하고 환승에는 적용하지 않는다.
- 전체 감시 cycle 소요시간을 SUMMARY에 출력한다.
- 후속 polling 기본값을 120초로 조정했다.
- 모든 rail target에서 직통과 환승을 별도로 항상 검색한다.
- 환승 시간표는 좌석 유무와 관계없이 실사용 지리 필터를 통과한 조합을 상세 출력한다.
- `transfer_display_direct_threshold`는 환승 검색/표시 조건이 아니라 이용 가능한 직통 선택지가 부족할 때 환승 후보를 실제 알림 대상으로 승격하는 기준으로만 사용한다.
- 카카오 알림 선두에서 `예약 가능`, `예약대기`, `좌석 품질 상승` 상태를 명확히 구분한다.
- Kakao `나에게 보내기`는 로그인 동의, 인가 코드 수신, 토큰 로컬 저장, 실제 테스트 메시지 발송까지 검증했다.

### 검증 이력

- 알림 메시지 생성 smoke에서 버스 `예약 가능`, 철도 `예약 가능`, 철도 `예약대기`, 철도 `좌석 품질 상승` 네 상태 구분을 확인했다.
- Python 구문 검사와 주요 모듈 import smoke를 통과했다.
- 공개/로컬 JSON 설정 파싱과 로컬 설정 우선순위 검증을 통과했다.
- 공개 target 템플릿에 개인 일정이 없고 `.env.local`, `watch_targets.local.json`, `*.gdoc`가 Git 추적되지 않는 것을 확인했다.
- 실제 외부 반복 조회에서 철도 공급자 정상 응답과 차단/NetFunnel 경고 부재를 확인한 이력이 있다.
